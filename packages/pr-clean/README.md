# @cteic/pr-clean

Checks a branch for the mistakes an unattended coding agent makes before its pull request goes public: commits under the wrong identity, co-author trailers, tool credit lines and em dashes. It runs as a CLI, a pre-push hook or a CI step. It uses only Node built-ins and has no runtime dependencies.

```text
pr-clean: FAIL
  2 commits checked against origin/HEAD (18fc314)

  author       fail  2 findings
  trailers     fail  1 finding
  attribution  pass
  em-dash      pass

author
  4f2a9c1  author: The author is not on the allowed list
      Some Tool <tool@example.com>
  4f2a9c1  committer: The committer is not on the allowed list
      Some Tool <tool@example.com>
  Set your identity, then rewrite the commits with it:
    git config user.name "<name>" && git config user.email "<email>"
    git rebase <base> --exec 'git commit --amend --no-edit --reset-author'

trailers
  4f2a9c1  co-authored-by: Commit message: A co-author trailer
      Co-authored-by: Some Tool <tool@example.com>
  Reword the commits and delete those lines:
    git rebase --interactive <base>
```

## Install

```sh
pnpm add --save-dev @cteic/pr-clean
```

Needs Node 24 or later and git.

## Usage

```sh
pnpm exec pr-clean --allow-author "Ada Example <ada@example.com>"
pnpm exec pr-clean --base origin/dev      # compare with another ref
pnpm exec pr-clean --pr-body-file body.md # also check the PR text
pnpm exec pr-clean --skip em-dash         # turn one rule off
pnpm exec pr-clean --json                 # machine-readable report
pnpm exec pr-clean --dry-run              # report, but always exit 0
```

## Rules

`pr-clean` reads the commits in `<base>..HEAD` and the lines the branch adds since the merge base. It never reads lines that were already on the base, so old text cannot fail a new branch.

| Rule          | Fails when                                                                                          | Reads                                                             |
| ------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `author`      | A commit's author or committer is not on the allowed list. Both must match `Name <email>` exactly   | Commits                                                           |
| `trailers`    | A commit message holds a co-author trailer, a credit line or a tool session link                    | Commit messages                                                   |
| `attribution` | An added line, or the PR body, credits a coding tool                                                | Added lines, PR body                                              |
| `em-dash`     | An em dash (U+2014) appears in an added line of a prose file, in a commit message or in the PR body | Added lines of `.md`, `.mdx` and `.txt`, commit messages, PR body |

The `author` rule has no default list. With no allowed author and no `--skip author`, `pr-clean` exits 2 instead of passing a check it did not run.

A commit that GitHub creates in the browser, such as a merge or an applied suggestion, has the committer `GitHub <noreply@github.com>`. Add that identity to the list if your branches hold such commits.

### Credit patterns

The `trailers` and `attribution` rules share one short pattern list, in [`src/patterns.ts`](src/patterns.ts). Each pattern has a test.

| Pattern           | Matches                                                                                | Checked in               |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------ |
| `co-authored-by`  | A line that starts with `Co-authored-by:`                                              | Commit messages, PR body |
| `generated-line`  | A line that starts with `Generated with` or `Generated by`                             | Commit messages          |
| `session-trailer` | A trailer such as `<Tool>-Session:` for a known coding tool                            | Commit messages, PR body |
| `generated-link`  | `Generated with` or `Generated by`, then a Markdown link                               | Added lines, PR body     |
| `generated-tool`  | `Generated with`, `by` or `using`, then the name of a known coding tool                | Added lines, PR body     |
| `built-with-tool` | `Built`, `written`, `created`, `made` or `authored` `with` or `by` a known coding tool | Everywhere               |
| `session-link`    | A link to a coding tool session                                                        | Everywhere               |

Ordinary product text passes: `Code generated by protoc-gen-go`, `Built with TypeScript` and `Docs are generated by the build` match nothing. Tool names are case-sensitive, so `rows created by cursor` passes.

### When a match is real product text

- End the line with a comment that holds `pr-clean-allow`, for example `<!-- pr-clean-allow -->` in Markdown or `// pr-clean-allow` in code. The `attribution` and `em-dash` rules skip that line.
- Or skip whole files with `--ignore <glob>` or the `ignore` config key.

When `pr-clean` checks the repo that holds its own source, it skips its own `src/patterns.ts` and `src/**/*.test.ts`, because those files must hold the text they search for.

## Options

| Option                    | Default                  | What it does                                                          |
| ------------------------- | ------------------------ | --------------------------------------------------------------------- |
| `--base <ref>`            | `origin/HEAD`            | Ref to compare with                                                   |
| `--allow-author <author>` | none                     | Allowed `Name <email>`. Repeatable. Adds to the config list           |
| `--skip <rule>`           | none                     | Turn a rule off. Repeatable                                           |
| `--pr-body-file <path>`   | none                     | Also check the PR body in this file                                   |
| `--ignore <glob>`         | none                     | Skip matching paths in `attribution` and `em-dash`. Repeatable        |
| `--em-dash-files <glob>`  | `*.md`, `*.mdx`, `*.txt` | Files the `em-dash` rule reads. Repeatable. `'*'` checks code as well |
| `--json`                  | off                      | Print the report as JSON                                              |
| `--dry-run`               | off                      | Report, but always exit 0                                             |
| `--version`               |                          | Print the version                                                     |
| `--help`                  |                          | Print the help                                                        |

A glob with no `/` matches the file name in any directory: `*.md` matches `docs/a.md`. A glob with a `/` matches the whole path from the repo root.

## Exit codes

| Code | Meaning                                                                           |
| ---- | --------------------------------------------------------------------------------- |
| `0`  | No findings                                                                       |
| `1`  | At least one finding                                                              |
| `2`  | Usage error, bad config, no allowed author, or a git error such as a missing base |

## Config

Put defaults in `.pr-clean.json` at the repo root, or under a `pr-clean` key in `package.json`. `.pr-clean.json` wins when both exist. List flags add to the config lists. `--base` and `--em-dash-files` replace the config value.

```json
{
  "base": "origin/dev",
  "allowAuthors": ["Ada Example <ada@example.com>"],
  "skip": [],
  "ignore": ["CHANGELOG.md"],
  "emDashFiles": ["*.md", "*.mdx", "*.txt"]
}
```

## JSON report

```json
{
  "verdict": "fail",
  "dryRun": false,
  "base": { "ref": "origin/HEAD", "sha": "18fc314..." },
  "commits": 2,
  "rules": [
    {
      "rule": "author",
      "status": "fail",
      "findings": [
        {
          "rule": "author",
          "check": "committer",
          "location": { "kind": "commit", "commit": "4f2a9c1..." },
          "message": "The committer is not on the allowed list",
          "excerpt": "Some Tool <tool@example.com>"
        }
      ]
    }
  ]
}
```

`status` is `pass`, `fail` or `skipped`. A `location` is a commit, a file with a line number (`"kind": "file"`), or a line of the PR body (`"kind": "pr-body"`).

## Commit subjects

`pr-clean` does not check Conventional Commits. `@cteic/commitlint-config` owns that rule, and commitlint checks the same range:

```sh
pnpm exec commitlint --from origin/dev --to HEAD
```

## Pre-push hook

Save as `.git/hooks/pre-push` and make it executable, or call the same line from your hook manager. Keep the allowed author in the config file so the hook stays one line:

```sh
#!/bin/sh
exec pnpm exec pr-clean --base origin/dev
```

git stops the push when `pr-clean` exits 1.

## CI

Check out the pull request's head commit with full history. The default checkout is a merge commit that GitHub creates, and its committer is not yours.

```yaml
name: PR clean

on:
  pull_request:

permissions:
  contents: read

jobs:
  pr-clean:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          ref: ${{ github.event.pull_request.head.sha }}
          fetch-depth: 0
          persist-credentials: false
      - uses: pnpm/action-setup@73e46992e05b19abd31f2f3c20e0e7370d762115 # v6.1.1
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 24
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - name: Check the branch and the PR text
        env:
          PR_BODY: ${{ github.event.pull_request.body }}
          BASE_REF: ${{ github.base_ref }}
        run: |
          printf '%s\n' "$PR_BODY" > "$RUNNER_TEMP/pr-body.md"
          pnpm exec pr-clean --base "origin/$BASE_REF" --pr-body-file "$RUNNER_TEMP/pr-body.md"
```
